## Routing defect found and fixed

Changing from the protected feed to a signed-out or suspended session could enter
an infinite redirect loop. Both protected stacks redirected to `/`, which also
matches the pathless tabs group's index. Redirecting from that group could target
its protected index again rather than the public account handler.

A distinct public `/account` route now reuses the existing root account/session
screen. Both guards redirect there. Authentication, suspension and onboarding
checks remain in that handler, and backend authorization remains unchanged.

Evidence:

- Before: native iOS displayed `Maximum update depth exceeded` and no usable screen.
- The added Router regression test opening a protected tab with a suspended session
  reproduced the loop before the fix (the process ultimately exhausted its heap).
- After: the regression test passes; existing onboarding navigation still passes.
- Native Home → authentication now reaches Welcome (`07-welcome-fixed.png`).
- Native loading-feed → suspended account reaches the account message without a
  loop (`65-account-unavailable.png`). Sign out reaches Welcome (`66-sign-out-welcome.png`).
- Independent code review found no actionable issues in the fix or regression test.

This resolves the transition left unverified in the earlier Android report. The
initial Android note attributed it to possible harness navigation timing; the iOS
run and Router regression established that the app's shared redirect destination
also needed correction. No experimental harness navigation changes were retained.
The corrected transition was verified natively on iOS, not rerun on Android here.

## Limits

This was a fake-data screen and interaction walkthrough, not live-service acceptance.
Google/Facebook OAuth, email delivery, real upload/storage persistence, server-side
mutation effects, camera capture and physical-device behavior were not verified by
this run. Publishing used the fake upload response and returned an existing fixture
post. Not every action on every screen was submitted. Dark mode and larger text
were not retested; simulator appearance and accessibility settings were left unchanged.
